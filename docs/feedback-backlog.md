# 사용자 피드백 백로그

첫 링크 테스트(2026-08, 지인 대상)에서 받은 코멘트와 그 처리 계획.
**아직 아무것도 적용하지 않았다.** 다음 수정 라운드에서 합의된 것부터 넣는다.

---

## 받은 코멘트 원문

1. 중간중간 선택지가 있는 거 좋음 (지루하지 않음)
2. 책에 대해 배경지식이 없는 사람은 내용이 잘 이해가 안 됨
3. 번역에 어색한 부문이 많음 (비문 다수)
4. 다 읽고 나면 그냥 작품만 다시 읽어보는 형태로 (다시읽기 / 선택지 없이 읽기) 형태 추가 필요
5. 어투가 좀 끊어지는 느낌. 내가 수정할 수 있도록 만드는 것과, 기본적인 어투를 레퍼런스로 먹이면 그 톤엔 매너로 제작할 수 있을지

---

## F1 — 배경지식 없으면 이해가 안 된다

**결정: UI로 해결하지 않는다. 본문을 다시 쓴다.**
**규모: 대. 작품당 반일~하루. 코드 변경 0.**

표지에 「들어가기 전에」를 붙이는 안, 페이지별 각주를 다는 안은 **둘 다 폐기했다.**
그 자리는 나중에 출판사 고전 전집 같은 광고가 들어갈 수 있는 자리이고,
설명을 덧붙여 이해시키는 것은 애초에 이 앱이 하려는 일이 아니다.

대신 **각색문 자체가 배경을 감당해야 한다.** 원작을 한 번도 안 읽은 사람이
읽어도 줄거리가 서고 시사점이 남아야 하며, 다 읽고 나면 **원작이 읽고 싶어져야 한다.**
이것이 세 작품 공통의 각색 목표로 추가된다.

각색 원칙에 두 줄을 더한다 (세 작품 md의 「각색 원칙」과 `docs/new-work.md`).

- 원작을 안 읽은 사람 기준으로 쓴다. 인물이 처음 나오면 그 사람이 누구인지가
  장면 안에서 드러나야 한다. 설명 문단을 따로 두지 않고 장면으로 처리한다.
- 다 읽고 나면 원작이 읽고 싶어져야 한다. 요약이 아니라 발췌의 감각으로 쓴다 —
  다 보여줬다는 느낌이 들면 실패다.

어느 대목이 막히는지는 `/admin`의 페이지별 이탈률로 좁힌다. 추측으로 고치면
안 막히는 데를 고치게 된다. 그래서 이 항목은 데이터를 본 뒤 3차 라운드에 둔다.

우선 손볼 후보(현재 원고를 읽고 추린 것):
- 『이방인』 6~8페이지 — 2부 재판이 1부 사건을 독자가 붙들고 있다고 전제한다
- 『변신』 4페이지 — 가족의 돈 사정이 한 번 스치고 지나간다
- 『시지프 신화』 7페이지 — 신화로 넘어가는 낙차가 의도한 것이지만, 시지프가
  누구인지 모르는 사람에게는 그냥 갑작스러울 수 있다

## F2 — "번역에 어색한 부문이 많음 (비문 다수)"

**규모: 중. 코드 변경 0, 원고 교정.**

먼저 사실관계 하나. 이 앱에는 번역문이 없다. 출판 번역본은 한 줄도 쓰지 않았고
전부 원문 기반 자체 각색이다(저작권 요건). 그런데도 테스터가 "번역"이라고 부른 것은
**문장이 번역투로 읽힌다**는 뜻이므로, 그 자체가 정확한 지적이다.

원인 후보:
- 원문 구조를 그대로 따라간 문장 (특히 『이방인』 1인칭 과거 나열)
- 주어를 생략해도 되는 자리에서 "나는"을 반복
- "~것이었다", "~하는 것이다" 남발
- 한 문장에 절이 셋 이상 들어간 대목

**손댈 곳:** `content/*/ko.md` 세 편의 본문. 문항과 json은 건드리지 않는다.
**규모:** 작품당 2~3시간.

**문제는 어느 문장이 걸렸는지 모른다는 것.** 두 가지로 좁힌다.

- 자동 검사를 `content:check`에 warn으로 추가 (반일): 한 문장 60자 초과, 한 문단
  안의 "것" 3회 초과, 이중피동(되어지다·불려지다), 같은 종결어미 4연속.
  기계가 잡을 수 있는 것만 잡는다. 나머지는 사람이 읽어야 한다.
- 문장 신고 버튼은 **폐기.** 읽기 화면에 버튼을 하나 더 두는 값이 얻는 것보다 크다.
  어색한 대목은 테스터에게 말로 받는다.

## F3 — 다시읽기 / 선택지 없이 읽기

**규모: 소. 반일. 다음 수정 1순위로 제안한다.**

가장 명확하고 가장 싸다. `readingPayload()`가 이미 전 페이지 본문을 주고,
세션 없이도 만들 수 있다. 필요한 것은 라우트 하나다.

- `app/reread/[slug]/page.tsx` — 세션 불필요, 문항 렌더 안 함, 열 페이지를 한 스크롤로.
  삽화는 그대로, 진행 표시는 없음.
- 진입점 둘: 결과 화면 하단("선택지 없이 다시 읽기"), 표지(**이미 완독한 작품일 때만**).
- 서비스 워커 프리캐시 목록(`components/PrefetchPages.tsx`, `public/sw.js`)에 이 경로 추가.

**결정됨: 완독 후에만 노출한다.** 열어두면 문항을 통째로 건너뛰고 결과만 보러
갈 수 있어 데이터가 오염된다. URL을 직접 치면 열리는 것까지 막지는 않는다.

## F4 — 어투가 끊어진다 / 톤 레퍼런스

코멘트가 두 가지를 한꺼번에 말하고 있어 나눠 본다.

### (b) 기본 어투를 레퍼런스로 먹이기 — **규모: 소. 반일. 권장.**

지금 톤 지침은 `docs/spec.md`와 각 작품 md의 「각색 원칙」에 흩어져 있고,
"짧은 문장, 현대 구어 리듬, 감정 형용사 절제" 정도로만 적혀 있다. 이 정도로는
작품이 늘어날수록 톤이 흔들린다.

`docs/style.md`를 만든다. 들어갈 것:
- 문장 길이 분포(중앙 25~35자, 60자 넘는 문장은 페이지당 하나까지)
- 종결어미 배분과 4연속 금지
- 금지 어휘: 철학·문학 용어, 감정 형용사, 번역투 관용구 목록
- 대화 처리 방식(따옴표를 쓰지 않고 문장에 녹인다 — 세 작품이 이미 그렇게 돼 있다)
- 좋은 문장 / 고쳐야 할 문장 대조표 (기존 세 작품에서 실물로 뽑는다)

이게 있으면 다음 작품에서 내가 지킬 근거가 되고, F2의 자동 검사도 이 문서를
기준으로 짤 수 있다. **F2·F4가 사실상 한 작업이므로 묶어서 한다.**

### (a) 내가 직접 수정할 수 있게 — **결정: GitHub 웹에서 직접 고친다. 완료.**

앱 안에 편집 화면을 만드는 안은 폐기했다(인증·저장·정합성 검사·재빌드가 전부
필요해서 며칠짜리인데, 원고는 세 편이고 고치는 사람은 한 명이다).

사용법은 `docs/edit-content.md`에 정리했다. 요점 셋:
- GitHub 웹에서 `content/<작품>/ko.md`를 연필 아이콘으로 고치고 커밋한다
- **자동 반영되지 않는다.** 노트북에서 `git pull` → `npm run build` → `npm start`
- 본문은 마음대로, `> **Q…**` 문항 블록과 `## 1. 제목` 줄은 건드리지 않는다
  (json과 대조되므로 빌드가 실패한다)

---

## F5 — 중간중간 선택지가 좋다

유지. 문항 수를 늘리고 싶은 유혹을 경계한다. 현재 8~12개이고, 이보다 늘리면
"읽는 중 묻는다"가 "설문 푼다"로 바뀐다. 지루하지 않다는 반응은 문항 수가 아니라
문항이 장면 안의 행동으로 위장돼 있어서 나온 것에 가깝다.

## 제안 순서

| 라운드 | 항목 | 예상 |
|---|---|---|
| **1차** | F3 다시읽기 · F4(b) `docs/style.md` · 각색 원칙 두 줄 추가 | 하루 |
| **2차** | F2 세 편 교정 패스 + 자동 검사 warn | 이틀 |
| **3차** | F1 각색문 재작업 — `/admin` 이탈 페이지 확인 후 | 작품당 반일~하루 |

시지프 삽화 교체는 이와 별개로 언제든 들어갈 수 있다.

## 결정된 것

1. **F4(a)** — GitHub 웹에서 md 직접 편집. 앱 내 편집 화면은 폐기. 사용법은
   `docs/edit-content.md`
2. **F3** — 다시읽기는 완독 후에만 노출
3. **F1** — 표지 안내문·각주 둘 다 폐기. 본문이 스스로 배경을 감당하게 다시 쓴다.
   그 자리는 나중에 출판사 광고가 들어갈 수 있다
4. **F2** — 문장 신고 버튼 폐기. 어색한 대목은 테스터에게 말로 받는다

## 새로 생긴 목표

**다 읽고 나면 원작이 읽고 싶어져야 한다.** 이건 피드백 대응이 아니라 BM과
직결된다 — 출판사 고전 전집 광고가 결과 화면에 붙는다면, 그 광고가 먹히는
유일한 조건이 이것이다. 각색은 요약이 아니라 발췌의 감각이어야 한다.
