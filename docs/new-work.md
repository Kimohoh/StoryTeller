# 작품 하나 더 붙이기

『변신』을 만들며 밟은 지뢰를 순서로 굳혀 둔 문서다. 이 순서를 지키면 코드는 건드리지 않는다.

---

## 순서 — 이 순서인 이유가 있다

### 1. 자리부터 만든다

```bash
npm run work:new -- <슬러그> --pages 10 --questions 8
```

폴더·레지스트리·manifest·설명문 자리가 한 번에 생긴다. 슬러그는 URL에 그대로 들어가므로
영문 소문자·숫자·하이픈만 쓴다. 새 작품은 `status: "draft"`로 들어가 서재에 안 뜬다 —
직접 URL로만 열린다.

### 2. 정본을 쓴다

`content/<슬러그>/ko.md` 가 사람이 읽고 고치는 정본이고, `ko.json` 이 구조다.
**같은 질문 문장이 두 파일에 들어가므로 어긋나면 빌드가 실패한다** — 그러라고 만든 검증이다.

```bash
npm run content:check
```

### 3. 삽화를 받는다

```bash
# incoming/ 에 <작품>_1.png … 올린 뒤
npm run illustration:batch -- --work <슬러그>
npm run illustration:optimize
```

원본은 보통 장당 2~3MB다. **optimize를 반드시 돌린다** — 『변신』은 22.4MB가 1.8MB가 됐다.
안 돌리면 폰에서 한 작품 읽는 데 20MB를 쓰고 프리뷰는 발행 한도를 넘는다.

### 4. 진단문과 논거를 쓴다

`ko.results.json` 의 `types.*.paragraphs`(유형당 3단락), `choice_quotes`(선택지마다 한 줄),
`seed_arguments`(선택지마다 논거). `draft: true`인 동안 결과 화면에 미작성 배너가 뜬다.

### 5. 공개한다

`content/works.json` 의 `status` 를 `published` 로 바꾸면 서재에 뜬다.

```bash
npm run content:build && npm run preview   # 폰으로 최종 검수
git push                                    # 배포는 fly deploy (docs/deploy.md)
```

## 『변신』에서 밟은 지뢰

**문항 id는 작품별로 네임스페이스한다.** `questions.id`는 전역 PK라 두 작품이 다 `q1`을
쓰면 시드가 서로 덮어쓴다. 스캐폴드는 `<슬러그>-q1` 로 만들고, 빌드가 작품 간 충돌을 잡는다.
(『변신』만 `q1…q8`을 그대로 쓴다 — 먼저 만들어졌고 이미 답이 쌓여 있어 두었다.)

**삽화 키는 작품 안에서만 유일하면 된다.** manifest가 `슬러그 → 키 → 에셋`이라
새 작품도 `p1_morning` 을 다시 써도 부딪히지 않는다.

**축은 B-A-B-A로 교차해야 한다.** 한 축 문항이 몰리면 사람들이 앞 답에 맞춰 일관성을
만들어 좌표가 뭉개진다 (spec §4). 빌드가 검사한다.

**문항 수는 달라도 된다.** 누적 좌표는 작품별로 먼저 좌표를 낸 뒤 평균하므로,
열 문항짜리가 여덟 문항짜리를 밀어내지 않는다. 작품은 각각 한 표씩 갖는다.

**진단문 ①단락은 특정 선택을 단정하지 않는다.** 경계 근처 사람은 두세 개를 반대로 골랐고,
고르지 않은 답을 골랐다고 쓰는 순간 진단문 전체의 신뢰가 무너진다. "~쪽으로 기울었습니다"로
쓰고, 구체적인 지목은 `choice_quotes` 가 맡는다.

**가중치 1.2짜리를 여럿 두면 인용문이 한 문항에 고정된다.** 점수가 동점이면 가장 오래
망설인 문항으로 갈리게 해뒀지만, 애초에 무게를 다양하게 주는 편이 낫다.

**cold start 논거는 코멘트가 아니다.** `comments` 테이블에 넣지 말 것. 화면에서도
"편집부가 미리 써둔 말"로 명시한다 — 유저 글로 위장하면 들키는 순간 끝이다 (spec §9).

**유형 이름에 가치 서열을 두지 않는다.** 한쪽이 더 성숙하거나 따뜻해 보이면 다음 작품부터
사람들이 그쪽으로 답한다 (spec §2). 진단문 ③(사각지대)이 네 유형 모두에 실제로 아파야 한다.

## 삽화 사양 (요약)

전문은 `docs/illustration-brief.md`.

- **9:16 세로**, 1080×1920 이상, PNG 또는 WebP
- 읽을 수 있는 **문자를 넣지 않는다** — 『변신』 1차 시안의 장부에 한글이 들어가 재작업했다
- 팔레트 다섯 색 고정, 사람 얼굴 없음
- 파일 이름은 페이지 번호만 알아보면 된다 (`이방인_1.png`, `p1.png`, `1.png` 전부 인식)
